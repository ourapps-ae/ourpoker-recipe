# OurPoker application-specific component

## Purpose and facilities
Package `ourapps-ae/ourpoker` version 0.3.3, kind `recipe`. It is the part of the OurPoker recipe no general component provides: the house rules file, the screen flow (home, name, lobby, seat, table, results) on web, Apple and Android, the poker table drawing (betting controls, hand text, showdown display, odds display), the wiring that selects the server components and connects them, the application's text in English, French, German and Spanish, the lessons, the artwork and sounds, the desktop entry, and the end-to-end test specs. Facility `application`. It provides the poker game adapter; display-mode, video-calls and windows-desktop take their configuration in code (their `configuration` requirement is optional), so it provides no configuration port. The recipe's page, questions and component list are in `recipe.json`; the assembled application is built from the 39 components plus this one.

## User inputs
Seventeen settings, each with a default, adapted to aepm's grammars: `applicationId` (slug), `applicationName` (label), `packageId` (qualified), `scheme` (slug; the desktop URL scheme and native origin, lower case), `serverAddress`, `webAddress`, `inviteAddress` (address), `roomPrefix` (slug, ends with a hyphen), `modeEvent` (slug), `updatesEnabled` (boolean), `signingEnvironmentPrefix` (environment), and the six answers that change the house rules: `maximumPlayers`, `startingStack`, `levelSeconds`, `rebuysPerPlayer`, `decisionSeconds` (integers) and `computerPlayers` (slug: `none`, `on-request` or `fill-empty`, the computer-players component's `mode`). `server/src/rules.ts` writes those six over the house rules file when the server starts, and every component is built from the result, so the rules file stays the one source of the game's numbers; `recipe.json` sets the matching component settings from the same answers (`application.<setting>` targets). No secret is collected: accounts and keys are given by reference to the components that need them (server-host, ourapps-release, video-calls). The recipe's questions set `webAddress` (default `http://localhost:5173`), `inviteAddress` (when updates are on), `packageId` (when `bundleId` is answered; the default `app.ourapps.ourpoker` is the derived one) and the six rules answers; `serverAddress` has its local default until the server is deployed (INTEGRATION-GAPS.md G10.3). The Apple project folder is fixed as `OurPoker`: apple-host's `scheme` setting must be `OurPoker`, as `recipe.json` sets it.

## Artefacts and dependencies
`component.json` maps every implementation, rules, text, art, sound and test file to its place in the application (`server/`, `web/`, `ios/OurPoker/`, `android/app/`, `desktop/`, `rules/`, `resources/`, `verification/`); none goes under `components/`. Files that name a setting are templates (10); the installer's own substitution is run on each one by `scripts/make_component.py`. `dependencies` is empty: the code imports from 34 components by the paths `components/<name>/<platform>/...`, which exist only because the recipe's `components` list at exact versions put them there, so the layout is the recipe's, not this package's. Tools: node 26.5.0, python3 3.12.8, swiftc 6.4.2, kotlinc 2.2.0, java 26.0.1 (`tools.lock.json`). 34 artefacts carry `component: "ourapps-ae/<name>"` (computer-players 1, guided-tour 3, store-update 9, video-calls 14, web-host 1, windows-desktop 6): the files whose imports or paths name an optional component, installed only when the design includes it (rule 25; marked by `scripts/make_component.py`, checked by `authoring/check_conditional_artefacts.py`). Core files that import those modules are not conditional, so a design without the component does not compile (INTEGRATION-GAPS.md G10.4).

## Provided interfaces
One file each in `interfaces/` describes them.
- `poker-game-adapter` (`ae/game-adapter`): `pokerAdapter(links)` in `server/src/adapter.ts`, turn-engine's adapter answering in the poker wire view (`server/src/contract.ts`, contract version 1) that the four clients decode. `recipe.json` connects this port to realtime-rooms' `game` requirement (the clients and the wire fixtures expect the poker view) and turn-engine's own adapter to this component's `game-adapter` requirement.

## Required interfaces
Twenty ports, named by the type's last segment: `game-adapter` (turn-engine), `web-shell`, `apple-shell`, `android-shell`, `desktop-host`, `server-host`, `release-pipeline`, `invitations`, `display-policy`, `media-session`, `table-layout`, `card-graphics`, `chip-graphics`, `sound-cues`, `guided-tour`, `updates`, `controls`, `preferences`, `language`, `theme`. Seven are marked `optional`: `web-shell`, `apple-shell`, `android-shell`, `desktop-host`, `media-session`, `guided-tour` and `updates`, whose providers the recipe includes only for some answers (`includedWhen`); `recipe.json` drops the connection when the provider is left out. `interfaces/required/<port>.json` lists, per port, the names the code imports from the providing component. The server also composes seating, tournament, computer-players, holdem-rules, game-clock, presence, private-views, round-history, chip-ledger, level-schedule, rules-settings, card-deck, poker-hand-ranking, poker-odds, poker-strategy, guest-identity and room-directory by import, each through its own interface (`server/src/parts.ts`; guest-identity's `createIdentityApi()` is passed to seating and, as `services.identity`, to realtime-rooms in `room.ts`); those are listed in `recipe.json`, not here, because they are reached through turn-engine's parts rather than a port of this component.

The server wiring has no adapter between a provider and its consumer: game-clock, private-views, presence, round-history, chip-ledger, level-schedule, holdem-rules, poker-strategy and rules-settings provide the operations turn-engine, tournament and computer-players declare. The `// GAP:` marks are in the Apple and Android clients and are rows of `INTEGRATION-GAPS.md`.

## Integration
See `INSTRUCTIONS.md` for what to select and configure. After assembly: render the host files with the options below, generate resources, then build each target.
- web-host: `body` option from `web/page-body.html`; entry `src/main.ts`. Run the translations generator on `resources/strings.json` with `--web web/src --apple ios/OurPoker/Resources --android android/app/src/main/res`.
- apple-host: scheme `OurPoker`, component sources the Swift folders of the components this application imports; art and sounds are in the project's `Art` folder (folder reference).
- android-host: `activityName` `app.ourapps.ourpoker.MainActivity` (the Kotlin package is fixed, not the package id; every string and resource is looked up by name so no source names the package id), `permissions` `CAMERA` and `RECORD_AUDIO` plus `INTERNET`, `cameraOptional`, `componentFolders` the components' `android` folders. Sounds are `res/raw/snd_<cue>.wav` and the manifest `res/raw/sounds_manifest.json`; lessons `res/raw/lessons.json`; room art `res/drawable-nodpi/`.
- server: aepm renders `components/server-host/server/host-settings.ts` from server-host's settings (provider, accountReference, allowedOrigins, roomPrefix, region) and `server/src/index.ts` imports it; the worker is `server/src/index.ts`; the e2e harness (vitest configuration, wrangler bindings) is not part of this package.
- desktop: `desktop/src/main.cjs` calls windows-desktop's `start` with `desktopConfiguration(app)`.
Nothing in this package runs the recipe, resolves components or assembles the application.

## Visual definition and connected examples
`visual/definition.json` maps the one output and twenty inputs (seven optional) to the interfaces above and lists the seventeen settings. `visual/examples/connected.json` connects it to one stand-in for the rest of the application; the 39 components are drawn in the recipe page. Both image formats and a text description are in `visual/output/`. The generated diagram's DOCTYPE line is removed from the SVG for the catalogue (INTEGRATION-GAPS.md G7.17).

## Infrastructure
No service is deployed by this package and no account is needed to hold it. The servers, hosting, video and release accounts belong to server-host, video-calls and ourapps-release. Costs are unmeasured.

## Verification
`node --test tests/portable.test.ts` (required, package root) checks: the house rules file against its schema and the blind table; every string in four languages with identical placeholders; every lesson step's keys and the lesson ids the code asks for; every string key the screens name; the asset list against the files (sizes, hashes, under 5 MB, generic names); the sound and art manifests; the manifest's file list, destination map and template tokens; component paths the code imports; the wire fixtures; the configuration example (`examples/configuration.ts`).
Not run here: the end-to-end specs under `tests/e2e/` (server hand, two-player browser hand with a public display, reconnect, update, media, native hand-offs, Windows package). They need the assembled application and its harness. Swift files are checked with `swiftc` against the iOS simulator SDK and the components' Swift files, TypeScript with `tsc`, JavaScript and CommonJS files with a syntax pass; Kotlin files cannot be checked (kotlinc is not installed). The package's own suite does not compile against the components.

## Scenarios and presentation
Two people sit, the host starts, the player to act folds and the hand ends with every chip counted (`tests/e2e/server/hand.test.ts`). Two browsers play a hand with a public display showing the table and no private cards (`tests/e2e/web/browser.mjs`). A phone loses its connection and rejoins by name with a fresh view (`tests/e2e/web/session.test.mjs`). The connected diagram shows the application taking the shells, facilities and presentation components and giving the poker adapter back.

## Updates and removal
Patch updates replace files; no data is kept, so there is no `migration.json`. Removal deletes the owned files listed in `component.json`; the application's seats, tokens and stored preferences live on the server and the devices and are not touched.
